Selected Work

  1. 01 CLI / AUTOMATION

    Lark Drive Bulk Downloader

    A Go CLI for downloading files in bulk from public Lark and Feishu Drive shared folders. Lark’s web interface uses a virtualized scroller — only the first 50 items exist in memory on page load, and standard HTTP clients are redirected to authentication gateways before they can reach any files. This tool solves both problems: it uses a headless Chrome session via the Chrome DevTools Protocol to unroll the full folder index through automated scrolling, then streams each file concurrently to disk using a configurable worker pool. The resulting binary is self-contained and cross-platform.

    • Go
    • CDP / Headless Chrome
    • Concurrent I/O
    View repository
  2. 02 DEVELOPER TOOLING

    Static CMS

    An open-source static asset management system built around stable, permanent public URLs. The core design: when a file is replaced, its URL stays the same. The system stages the new object in S3, verifies database integrity, then deletes the old object atomically — no broken links during the transition. Raster images are automatically converted to WebP, EXIF data is stripped, SVG files are sanitized against embedded scripts, and JSON schemas are minified on upload. Access is controlled through tiered roles (superadmin, admin, editor, viewer).

    • TypeScript
    • Next.js
    • PostgreSQL
    • S3-compatible storage
    View repository
  3. 03 FULL-STACK APPLICATION

    Shortener URL

    An open-source URL shortener with a Go backend (Fiber framework) and a React frontend. Creates short links, generates QR codes with destination text overlay, tracks click counts and unique visitors per URL, and supports CSV batch import of up to 1,000 URLs per operation. A bulk QR download endpoint packages multiple QR images into a ZIP archive. The API applies rate limiting at 100 requests per minute per IP. No login required — client state is stored in IndexedDB.

    • Go
    • React
    • TypeScript
    • PostgreSQL

The enhanced version adds hidden and system folder scanning, full drive usage summary with percentages, and analysis of space not accounted for by visible folders — useful for locating pagefile, hibernation, and shadow copy allocations.

Engineering Approach

  1. I

    Solve the actual problem

    Understand what’s happening in practice before choosing a technology or designing a solution. A clear problem statement usually reveals a simpler path than what’s initially assumed.

  2. II

    Make systems work together

    Build APIs, automation, and data flows that reduce repetitive work and connect systems that need to exchange information. Integration work is often where the most friction actually lives.

  3. III

    Keep things maintainable

    Favor clear interfaces, predictable behavior, and practical documentation. Software that works at launch but can’t be understood or changed six months later is only half-finished.
